# standard-task-flow

个人标准任务流程（六步链）：把一件事从「模糊想法」推进到「干净交付」。

## 一句话

**拷问定案 → 决策（必要时）→ 计划 → 按准则执行 → 洁癖收尾**

## 六步链

| 步骤 | 动作 | 触发条件 | 产出物 |
|---|---|---|---|
| ① 素材/截图 | 读懂输入，确认要做什么 | 每次拿到外部素材先看清内容 | 内容要点 + 用途确认 |
| ② grill | 批量拷问，每条带推荐答案 | 有想法/任务需要定案 | 决策表 |
| ③ 三省六部制 | 多 Agent 对抗决策 | 仅当实在难以决定 | 最优方案结论 |
| ④ plan | 把定案落成执行计划 | 决策已定 | 计划文档 |
| ⑤ karpathy-guidelines | 按行为准则执行 | 计划在手 | 实际产出 |
| ⑥ neat-freak | 执行完对账收尾 | 执行完成 | 无残留、规则与事实对齐 |

## 关键规则

1. grill 带建议：每个前沿问题都给推荐答案，不是干问
2. 三省可选：不是每次都走，只在难以决定时叠加
3. 执行遵守 Karpathy 准则：先想清楚、简洁优先、精准修改、目标驱动
4. neat-freak 必收尾：执行完必须对账，删除候选需用户确认
5. 截图是输入层：读懂+确认用途发生在 grill 之前
6. 执行环节有分工细则：统筹 / 执行 / 验收三权分置，工具按能力映射（见正文）

## 执行环节分工（v1.1 增补）

**三权分置**：统筹负责理解需求、拆解、判断依赖、分派与最终验收，不重复实现已委派出去的工作；执行者一个任务内独立闭环（分析相关代码 → 实现修改 → 跑必要测试 → 修复自己引入的问题）；验收基于 diff / 测试 / 实际运行结果判卷，发现问题优先派回原执行者，只在跨模块设计、疑难或执行者解不了时亲自介入。

**派活前检查**：不为「多 agent」硬拆简单任务；按模块划分文件所有权，禁止两个 agent 同改一文件或同一核心模块；有前置依赖的先冻结接口、数据结构、约束再并行；优先级 正确性 > 可维护性 > 简洁性 > 开发速度，不做无必要的抽象与过度工程。

**角色与工具**：角色是任务内的分工，不是工具的固有属性，同一对工具在不同项目里角色可以互换。协议正文只写角色，工具与模型的对应关系集中一处维护，换代只改一处。
